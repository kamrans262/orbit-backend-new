# Orbit Relay — Stage 2 Part 2 backend handoff
## Scope and gates
Implemented proposed direct M13 encrypted message adapter; peer transport and original source approval remain outstanding. No deployment. The 5 API routes from Part 1 are retained. Production gates default false: ORBIT_RELAY_ENABLED, ORBIT_RELAY_SECURITY_REVIEWED, ORBIT_RELAY_PEER_TRANSPORT_REVIEWED, M13 E2EE gate, and audited relay.operations.enabled. Configure independent server Ed25519 64-byte secret (standard base64) outside code and logs only after approval; authenticated capabilities supplies public key and SHA256 key ID. Do not treat those flags or CI as certification. No unsupported source adapter, SOS, GPS, group or media forwarding.
## Wire contract for Stage 3
- Capabilities data: enabled, readiness, policy_revision, server_time, protocol_versions, content_types, limits, signing_key (id, public_ed25519). Pin key via authenticated HTTPS and verify against separately trusted key; do not trust token-provided keys alone.
- POST leases: scope_ref UUID M13 direct conversation; peer_device_ref UUID registered peer; device_key_id integer current M13 sender key version; protocol_version orbit-relay-direct-v1; content_type direct_message; client_nonce 64 lowercase hex characters (32 random bytes). Response: lease_id, expires_at, lease. Same nonce same live context returns same lease, conflict otherwise. Max 20 active per device. Token is base64url(raw compact UTF8 JSON claims without padding) + "." + base64url(Ed25519 detached signature over UTF8 "orbit-relay-lease-v1|" concatenated with raw JSON). Claims include sender and peer device keys/versions, roster hash, scope, source epoch, policy revision, kid, issued_at/expires_at Unix seconds. Do not advertise token or stable peer identifiers. Bind ephemeral peer channel and prove possession of leased keys; actual local transport belongs to Stage 3.
- POST reconcile: batch_id UUID; items list <= configured batch, <=5 MiB body, each envelope_id UUID, source_client_id UUID, lease_id UUID, digest lowercase SHA256, source_envelope (M13 client_id same as source_client_id, kind text/emoji/sticker/reaction/reply, protocol orbit-m13-olm-megolm-v1, group_epoch, list of all current device envelopes with only device_id,ciphertext_b64,protocol_header_b64). Canonical digest is SHA256 lowercase hex of compact UTF8 JSON array [scope_ref, source_client_id, kind, protocol, integer group_epoch, array of envelope objects sorted ascending by device_id]. Object fields in order device_id, ciphertext_b64, protocol_header_b64; unescaped slash; standard canonical padded base64. No media or plaintext. Stable IDs shared with HTTPS M13.
- Optional receipt: {nonce: envelope_id, peer_digest: lowercase SHA256, received_at: integer UTC Unix seconds within lease interval, signature_b64: standard base64 of Ed25519 signature using recipient's current M13 identity key}. Sign UTF8 string "orbit-relay-receipt-v1|lease_id|scope_ref|sender_device_id|peer_device_id|envelope_id|source_client_id|digest|peer_digest|received|nonce|received_at". Recipient computes peer_digest over compact UTF8 JSON array [scope_ref, source_client_id, kind, protocol, integer group_epoch, single recipient envelope object with device_id,ciphertext_b64,protocol_header_b64 in that order], using unescaped slash and standard padded base64. This permits verification of the recipient's own ciphertext without exposing other devices' envelopes. Timestamp checked against lease and server time. Verify before publication. Recipient receipt only, never read; server acceptance only after M13 send. Local peer receipt by itself is not proof of server acceptance.
- Item results: accepted/duplicate/retryable/rejected/expired, safe reason_code, source_ref (success only), peer_receipt_verified. Same IDs and digest dedupe; changed IDs/digest conflict. Expired or revoked lease never permits new source publication; client must fall back to existing HTTPS M13 using same ID where authorized. Sync GET returns own historical outcome records with peer verification flag; cursor scoped to device/account and expires in 15 min. Client must not treat old historical acceptance as current authorization.
- Admin overview, settings, audit retain existing UI. Settings invalidate outstanding lease rows; config revision also fails stale leases. No private content or device encounter history in Admin. Metrics are aggregate attempts, verified_receipt increments once per receipt. Proposed 7 day expiry-relative metadata cleanup, 30 day aggregate retention; hourly bounded job only deletes Relay metadata, not M13 source. These numbers and supported kinds require original Relay spec review.
## Verification
Tests added to OrbitM22RelayTest and dedicated isolated MariaDB CI workflow, including full M21 module regression and M13 test suite. CI verifies sequential idempotency, partial batches and key/receipt tampering; true multi-process concurrency and device testing remain Stage 4 evidence gates. See exact commit CI; source implementation is not equivalent to runtime acceptance. Original pp.56–60 unavailable; no claim of complete original PRD/TRD or radio interoperability.
- Relay API uses named per-operation device/account/IP rate limits in addition to existing global ceiling. No previous route throttle or messaging authorization was changed. Tests cover two trusted devices on same IP and separate capabilities bucket.
