# ORBIT M19 Stage 2 — Subscriptions & Billing
Baseline M23 backend 68de458a375da7e8a9518483bc00054445471afb. Branch feature/m19-billing-backend-admin-2026-11-24. Flutter unchanged. No deployment.

## Implemented
Five sandbox-only billing tables; six routes; StoreBillingProvider Google OAuth service-account JWT, subscriptionsv2.get and Google acknowledgement, authenticated RTDN push OIDC; Apple ES256 JWS certificate chain against explicitly configured root with Apple certificate extension OIDs, current subscription-status API and V2 notification intake. Canonical provider queries determine state, never client-reported price or tier. Stable opaque HMAC Google binding / UUID-shaped Apple appAccountToken; fixed 15-minute context; same owner and request body required; restore with signed/account-bound evidence; unique provider/environment/lineage. Sandbox production transactions rejected and production environment hard-disabled. Entitlement recomputed under owner lock on read and write, highest current eligible plan only, never extend during outage. Google acknowledgement work durable, Apple finish_permitted only after verified eligible transaction commit. Webhook intake authenticates then stores bounded encrypted reference, keyed event ID and lineage digest; worker CAS lease, bounded retry and canonical lookup; stale replaced token cannot reactivate. Existing core authorization unaffected. Sandbox erasure follows account deletion; event retention seven days, no live financial records. One Admin workspace: Plans & Products, Subscriptions, Billing Operations; revision/confirmation/reason, RBAC, existing MFA and layout, redacted metadata, no refunds or manual grants.

## Stage 3 API contract
GET /api/v1/billing/catalog?provider=apple|google returns data.environment=sandbox, revision, purchase_enabled, production_enabled=false, provider, products [{id,tier,product_id,base_plan_id,interval,available,capabilities}]. No prices; store SDK must query localized price. No products seeded. GET /api/v1/billing/entitlement returns environment, tier (null unknown), state, effective_until UTC, auto_renew, verified_at, revision, capabilities. Capabilities baseline only: ad_free=false, activity_days=30, moment_days=7, enhanced_sos=false, advanced_visibility=false, premium_themes=false; informational free defaults, not new source filters. POST purchase-context provider, product_mapping_id, client_request_id UUID. Response context_id, account_binding, expires_at, product_id, base_plan_id, environment. POST verify provider, mode purchase|restore, proof (Apple StoreKit 2 signed transaction JWS / Google purchase token), context_id for purchase, client_request_id UUID. Response status verified|pending, entitlement, finish_permitted; failures via sanitized HTTP 401/403/409/422/503. Retry same request body; restore does not charge. Store management is native; new overlapping purchase contexts blocked. Existing store-managed replacement may reconcile; no arbitrary downgrade or new checkout while active. Do not show sandbox tier as live entitlement. Client cache must not unlock any unavailable benefits. No new app screen or provider credentials in Flutter.

## Configuration and limitations
All live payments impossible in this implementation. ORBIT_BILLING_SANDBOX_ENABLED defaults false. Stable 32-byte base64 ORBIT_BILLING_BINDING_KEY required; protect it and never rotate casually without migration. Apple ORBIT_BILLING_APPLE_BUNDLE, ISSUER, KEY_ID, KEY_PATH, ROOT_CA_PATH (prefix ORBIT_BILLING_APPLE_). Google ORBIT_BILLING_GOOGLE_PACKAGE, SERVICE_ACCOUNT_PATH, PUSH_EMAIL, PUSH_AUDIENCE, PUSH_SUBSCRIPTION. Key files private outside web root. Actual signed Apple/Google sandbox store transactions and notification delivery require client console setup. Synthetic certificate fixtures are not Apple trust certification; certificate revocation/OCSP, trust-root rotation, real provider compatibility, Google deferred replacement/multi-line items, legacy ownership, concurrent race stress, provider reconciliation and legal retention review remain release gates. Client verification that fails must retry/restore explicitly; authenticated webhook reconciliation is automatic. No annual/trial, Stripe, manual grants, refunds, production provider route, financial reporting, or fake revenue. Original scope unavailable; paid history/advertising/advanced SOS/visibility/themes remain unapproved, not sold. Sandbox data only. No change to M20 placements, M7 retention, previous-module policies or production gates.
